# API веб-версии RevEx

- [OpenAPI 3.0, JSON](openapi.json) — импортируется в Swagger Editor, Postman и другие клиенты.
- [Сущности и связи](ENTITIES.md) — каталог, файлы, история, релизы и аудит обновлений.
- Работающий Swagger UI: `http://localhost:8082/swagger`.
- Спецификация работающего API: `http://localhost:8082/swagger/v1/swagger.json`.

Базовый адрес локального API — `http://localhost:8082`. Пути спецификации
начинаются с `/api`. JSON передаётся с `Content-Type: application/json`;
загрузка файлов — `multipart/form-data`, скачивание — двоичные данные.
Даты — ISO 8601, идентификаторы каталога — integer, идентификаторы установок,
предложений обновления и скачиваний — UUID.

## Доступ

Для Keycloak используется `Authorization: Bearer <access_token>`:
realm `revex`, audience `revex-api`, роли берутся из claim `roles`.
В Swagger UI токен вводится через Authorize. API также поддерживает
конфигурацию ActiveDirectory/IIS; JSON-снимок подготовлен для Keycloak.

| Действия | Требования |
| --- | --- |
| Чтение каталога, версий, файлов и истории | По умолчанию аутентификация и одна из ролей `user`, `moderator`, `administrator`. |
| Изменение контента, версий, файлов и истории | Политика `EditContent`: `moderator` или `administrator`. |
| Изменение категорий, состояний, тегов и групп; управление релизами и чтение аудита | Политика `AdministerCatalog`: `administrator`. |
| `POST /api/desktop-updates/report` | Явная `[Authorize]`, аутентификация и идентификатор пользователя в claims. |
| Публичные установщики, legacy release, проверка обновления, пакет и сообщение об ошибке предложения | `[AllowAnonymous]`; для пакета и сообщения об ошибке требуется ключ установки. |

В спецификации политика указана в `x-authorization-policies`; пустой массив
на защищённом методе означает отсутствие именованной политики.
Публичные методы имеют пустое `security`. Ключ установки передаётся в заголовке
`X-RevEx-Installation-Key`; анонимность метода не отменяет его проверку.

## Особенности запросов

`GET /api/content/query` принимает `CategoryIds`, `TagIds`, `Name`.
Массивы передаются повторением query-параметра, например
`?CategoryIds=1&CategoryIds=2&TagIds=3`. Все заданные теги должны присутствовать
на карточке; поиск по имени не учитывает регистр.

Загрузка превью: `POST /api/content/{id}/preview`, поле формы `File`.
Загрузка файла версии: `POST /api/content-versions/{id}/file`, поля `File` и `Role`.
Загрузка релиза: `POST /api/desktop-releases`, поле `File` с ZIP-архивом,
лимит запроса — 1 GiB. Состав архива описан в [руководстве по релизам](DESKTOP_RELEASES.md).

Основные ошибки: 400 — некорректные данные, 401 — нужна аутентификация,
403 — недостаточно прав, 404 — объект или файл отсутствует, 409 — конфликт.
Автоматическая валидация возвращает ValidationProblemDetails; часть бизнес-ошибок
возвращает объект `{ "message": "..." }` или пустое тело. Проверка обновлений
возвращает 503, если активный релиз ещё не опубликован.

Веб-клиенту не требуется посылать `X-RevEx-Desktop-Version`. Если этот заголовок
передан для API каталога, middleware дополнительно проверяет поддержку desktop
и может вернуть 409 с `code: desktop_version_unsupported`.

## Обновление спецификации

Из корня backend (`WEB/Backend/RevEx`):

```bash
dotnet run --project tools/OpenApiExport
```

Генератор использует реальные MVC-контроллеры и ту же конфигурацию Swagger, что
и API. Он записывает корневой `RevEx.Web/docs/openapi.json`, не запускает HTTP-сервер, не подключается
к MongoDB, PostgreSQL или Keycloak и не создаёт тестовые данные.
После изменения API пересоберите спецификацию и закоммитьте её вместе с кодом.
Документация хранится в корневой папке `RevEx.Web/docs` рядом с Docker Compose.

Полный [перечень маршрутов](API-ROUTES.md) доступен отдельно для просмотра без OpenAPI-клиента.
